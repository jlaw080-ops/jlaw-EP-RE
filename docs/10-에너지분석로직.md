> 소스(`v26.2.0` 태그)와 공식 문서 세트를 함께 검토한 결과입니다.
> 객체 목록과 개수는 `idd/Energy+.idd.in` 에서 **기계적으로 추출한 실측값**입니다.

# 1. 에너지 시뮬레이션 절차

## 1-1. 전체 흐름 — 6단계

```
[1] 입력 처리        IDD로 IDF/epJSON 해석 → 각 모듈의 GetInput 루틴이 자기 몫을 읽음
         ↓
[2] 사이징 계산      설계일 기준으로 부하 계산 → 기기 용량 자동 결정
         │           존 사이징 → 시스템 사이징 → 플랜트 사이징 (순서 고정)
         ↓
[3] 환경 루프        환경 = 설계일 1개 또는 연간 RunPeriod 1개
         ↓
[4] Warmup          첫날을 수렴할 때까지 반복 (결과 미기록)
         ↓
[5] 시간 루프        일 → 시 → 타임스텝. 각 타임스텝마다 아래 [6] 수행
         ↓
[6] 열평형 + 설비    Predict → SimHVAC → Correct → 기록
```

근거: `src/EnergyPlus/SimulationManager.cc` `ManageSimulation()` (240줄)
상세 루프 구조는 [`02-계산엔진.md`](02-계산엔진.md) 2-2절.

## 1-2. 타임스텝 1회의 내부 순서 — 가장 중요한 부분

EnergyPlus의 에너지 계산 논리는 **"예측 → 공급 → 보정"** 3박자입니다.

```
① Predict   존 설정온도를 맞추려면 몇 W가 필요한가?
            → ZoneTempPredictorCorrector.cc : PredictSystemLoads()
            ↓  (요구량)
② SimHVAC   그 요구량을 실제 설비가 얼마나 공급할 수 있는가?
            → 말단기기 → 공조계통 → 열원 → 전력 순으로 역방향 추적
            ↓  (실제 공급량)
③ Correct   실제 공급량으로 존 공기 온도를 다시 확정
            → 공급 부족분은 Unmet Hours 로 집계
```

**이것이 정적 계산법(ISO 13790, 국내 건축물에너지효율등급 평가 방식)과의 결정적 차이입니다.**

| | 정적 계산법 | EnergyPlus |
|---|---|---|
| 부하 ↔ 설비 관계 | 부하를 구하고 설비효율로 나눔 | **설비 성능이 실내온도에 되먹임** |
| 용량 부족 | 반영 안 됨 | **Unmet Hours 로 드러남** |
| 부분부하 효율 | 평균값 | **매 타임스텝 성능곡선으로 계산** |
| 축열 | 간이 보정 | **CTF/유한차분으로 동적 계산** |

> **실무적 의미**: EnergyPlus에서 "설비 용량을 줄였는데 에너지가 줄지 않는" 결과가
> 나오면 버그가 아닙니다. 용량 부족으로 실내온도가 벗어나 **다음 타임스텝 부하가
> 커진** 것입니다. Unmet Hours를 함께 봐야 결과를 해석할 수 있습니다.

## 1-3. 계산 계층 — 어디서 무엇이 계산되는가

```
ManageSimulation
    ManageWeather                  기상 조건 (일사·외기·풍속)
    ManageHeatBalance              ★ 열평형 총괄
        InitHeatBalance
            PerformSolarCalculations      태양위치·일사·음영
        ManageSurfaceHeatBalance   ★ 표면
            ManageInternalHeatGains       내부발열
            CalcHeatBalanceOutsideSurf    외표면 (외기·일사·복사)
            CalcHeatBalanceInsideSurf     내표면 (CTF/CondFD/HAMT)
            ManageAirHeatBalance   ★ 존 공기
                CalcAirFlow               침기·환기·창문개방
                ManageHVAC         ★ 설비
                    ManageZoneAirUpdates 'GET ZONE SETPOINTS'
                    ManageZoneAirUpdates 'PREDICT'      ← ①
                    SimHVAC                             ← ②
                    UpdateDataandReport
            UpdateThermalHistories        축열 이력
            ManageThermalComfort          쾌적성
```

(출처: `SimulationManager.cc` 2896~2925줄 주석의 공식 계층도)

# 3. 패시브·액티브 요소 구성 방법

## 3-1. ★ 핵심 — EnergyPlus에는 "패시브/액티브" 구분이 없습니다

입력 객체에 그런 분류가 존재하지 않습니다. 실제 구분선은 **존 열평형식에
어떻게 들어가는가**입니다.

```
존 공기 열평형식:

  (존 공기 열용량) × dT/dt
     = Σ(표면 대류)        ← 패시브: 외피를 통한 열
     + Σ(내부발열 대류분)   ← 패시브: 사람·조명·기기
     + Σ(침기·환기)        ← 패시브: 공기 유입
     + Σ(존간 유동)        ← 패시브
     + Q_sys               ← 액티브: 설비 공급량  ★ 이 항이 유일한 액티브 접점
```

**액티브 요소는 `Q_sys` 단 하나의 항으로 들어옵니다.** 그리고 그 `Q_sys` 를
계산하는 것이 설비 시스템 전체입니다. 이 구조가 모델 구성 방법을 결정합니다.

## 3-2. 4계층 구조 — 모델을 조립하는 방식

```
┌─────────────────────────────────────────────────────┐
│ [1] 존 (Zone)                                        │
│     외피·내부발열·침기·자연환기가 여기서 열평형         │
│     ▸ 패시브 요소는 전부 이 계층에 입력                │
└──────────────────┬──────────────────────────────────┘
                   │ ZoneHVAC:EquipmentConnections  ★ 접점
                   │ (존의 공기 유입·유출 노드를 선언)
┌──────────────────▼──────────────────────────────────┐
│ [2] 존 기기 (Zone Equipment)                          │
│     ZoneHVAC:*  또는  AirTerminal:*                  │
│     ▸ ZoneHVAC:EquipmentList 로 우선순위 지정          │
└──────────────────┬──────────────────────────────────┘
                   │ AirLoopHVAC (덕트)
┌──────────────────▼──────────────────────────────────┐
│ [3] 공조계통 (Air Loop)                               │
│     팬 + 코일 + 외기도입 + 전열교환                    │
└──────────────────┬──────────────────────────────────┘
                   │ Branch / Node (배관)
┌──────────────────▼──────────────────────────────────┐
│ [4] 열원 (Plant Loop / Condenser Loop)                │
│     냉동기·보일러·히트펌프 + 펌프 + 냉각탑·지중열교환기  │
└──────────────────┬──────────────────────────────────┘
                   │
┌──────────────────▼──────────────────────────────────┐
│ [5] 전력 (Electric Load Center)                       │
│     PV·풍력·연료전지·CHP + 인버터 + 축전지 + 변압기     │
└─────────────────────────────────────────────────────┘
```

**모델 구성은 위에서 아래로 내려가며 노드를 연결하는 작업**입니다.
계층을 건너뛸 수 없고, 각 계층의 출구 노드가 다음 계층의 입구 노드가 됩니다.

> **입문자가 가장 많이 틀리는 지점**: 노드 이름 불일치입니다. 오타 하나로
> "연결되지 않은 노드" 오류가 나고, 어디가 끊겼는지 찾기 어렵습니다.
> `eplusout.bnd` 가 노드 연결 관계를 전부 출력하므로 **연결 검증은 이 파일로** 하십시오.

## 3-3. 패시브 요소 구성 방법

### 외피 — 3단 구조

```
Material / WindowMaterial:*          재료 물성
        ↓  (층 순서대로 나열, 외부 → 내부)
Construction                          구성체
        ↓  (면에 배정)
BuildingSurface:Detailed / FenestrationSurface:Detailed
```

재료 49종 중 주요한 것:

| 분류 | 객체 | 용도 |
|---|---|---|
| 기본 | `Material` | 두께·전도율·밀도·비열 (4개 모두 필요) |
| 간이 | `Material:NoMass` | R값만. **표면층에 쓰면 공기 물성이 몰래 부여됨** ([`06`](06-CTF상세.md) 6-9절) |
| 공기층 | `Material:AirGap` | 열저항만 |
| 옥상녹화 | `Material:RoofVegetation` | EcoRoof |
| **창호 간이** | `WindowMaterial:SimpleGlazingSystem` | **U값·SHGC·가시광투과율만 입력** |
| 창호 상세 | `WindowMaterial:Glazing` + `Gas` + `GasMixture` | 층별 광학·열 물성 |
| 변색유리 | `WindowMaterial:GlazingGroup:Thermochromic` | 온도 의존 |
| 차양 | `WindowMaterial:Shade`/`Blind`/`Screen`/`Drape:EquivalentLayer` | |
| **PCM** | `MaterialProperty:PhaseChange`, `:PhaseChangeHysteresis` | 상변화재료 |
| 가변물성 | `MaterialProperty:VariableThermalConductivity`, `:VariableAbsorptance` | |
| **습기** | `MaterialProperty:HeatAndMoistureTransfer:*` (6종) | HAMT ([`08`](08-심화-기밀성능과결로.md)) |
| 국내 기준 대응 | `Construction:CfactorUndergroundWall`, `Construction:FfactorGroundFloor` | **지중 간이 (C/F 값 직접 입력)** |
| 내부 열원 | `ConstructionProperty:InternalHeatSource` | 바닥복사난방 매립 |
| 가상 경계 | `Construction:AirBoundary` | 존 분할용 가상벽 |

> **`WindowMaterial:SimpleGlazingSystem` 을 적극 쓰십시오.** 국내 창호 성적서는
> U값·SHGC만 주는 경우가 많습니다. 상세 광학 물성이 없을 때 이 객체 하나로
> 입력이 끝납니다. 다만 차양 제어나 BIPV 연동이 필요하면 상세 입력이 필요합니다.

### 패시브 전략별 입력 객체

| 패시브 전략 | 객체 |
|---|---|
| **기밀성능** | `ZoneInfiltration:DesignFlowRate` / `:EffectiveLeakageArea` / `:FlowCoefficient`<br>정밀: `AirflowNetwork:MultiZone:Surface:Crack` ([`08`](08-심화-기밀성능과결로.md)) |
| **자연환기** | `ZoneVentilation:DesignFlowRate` / `:WindandStackOpenArea` |
| **야간 환기** | `ZoneVentilation:*` + 스케줄, `FanPerformance:NightVentilation` |
| **지중 예냉/예열** | `ZoneEarthtube`, `ZoneEarthtube:Parameters` |
| **연돌 환기** | `ZoneThermalChimney` |
| **증발냉각 타워** | `ZoneCoolTower:Shower` |
| **외부 차양** | `Shading:Site`/`Building`/`Zone:Detailed`, `WindowShadingControl` |
| **가동형 단열** | `SurfaceControl:MovableInsulation` |
| **외부 통기층** | `SurfaceProperty:ExteriorNaturalVentedCavity` |
| **트롬브 월** | `Construction:AirBoundary` 조합 (EngRef p1584) |

> 객체입니다. 쿨튜브·연돌 환기를 **정량 평가**할 수 있습니다.

## 3-4. 액티브 요소 구성 — 2가지 경로

| 경로 | 방법 | 장점 | 단점 |
|---|---|---|---|
| **A. HVACTemplate** | 32개 축약 객체로 입력 → `ExpandObjects` 가 정식 입력으로 자동 확장 | 입력량이 1/10. 노드 연결 자동 | 표현 가능한 구성이 제한됨 |
| **B. 정식 입력** | `AirLoopHVAC` + `Branch` + `Node` 직접 연결 | 모든 구성 가능 | 입력량 많고 노드 오류 빈발 |

### 경로 A — HVACTemplate 조합표

```
HVACTemplate:Thermostat                         설정온도
      +
HVACTemplate:Zone:<형식>        ← 존마다 하나
      +
HVACTemplate:System:<형식>      ← 계통마다 하나
      +
HVACTemplate:Plant:<루프>       ← 열원 루프
```

| 계층 | 선택지 |
|---|---|
| Zone | `IdealLoadsAirSystem` `BaseboardHeat` `FanCoil` `PTAC` `PTHP` `WaterToAirHeatPump` **`VRF`** `Unitary` `VAV` `VAV:FanPowered` `VAV:HeatAndCool` `ConstantVolume` `DualDuct` |
| System | **`VRF`** `Unitary` `UnitaryHeatPump:AirToAir` `UnitarySystem` `VAV` `PackagedVAV` `ConstantVolume` `DualDuct` **`DedicatedOutdoorAir`** |
| Plant | `ChilledWaterLoop`+`Chiller`+`Tower` / `HotWaterLoop`+`Boiler` / `MixedWaterLoop` |

> **권고**: 초기 검토·대안 비교는 **A(Template)로 시작**하십시오. 특히
> `HVACTemplate:Zone:IdealLoadsAirSystem` 은 설비를 "무한 용량 이상적 공조"로 두어
> **순수 건물 부하만** 뽑아줍니다. 패시브 요소 VE 검토의 기준선으로 가장 적합합니다.
>
> 설비 자체가 검토 대상이 되는 단계에서 B로 전환하십시오.
> `ExpandObjects` 로 확장된 결과(`.epmidf`)를 보면 **B 작성법을 배우는 교재**가 됩니다.

# 4. 설비 시스템 구성 및 적용 방법

## 4-1. 구성 유형 3가지

| 유형 | 구조 | 대표 구성 |
|---|---|---|
| **존 단위 (Zone Equipment only)** | 존 ← 기기 (덕트·배관 없음) | FCU, PTAC, PTHP, VRF 실내기, 복사패널, 베이스보드 |
| **중앙 공조 (Air Loop)** | 존 ← 말단 ← 덕트 ← AHU | VAV, CAV, 이중덕트 |
| **중앙 공조 + 열원 (Air Loop + Plant)** | 위 + 냉온수 배관 ← 열원 | 냉동기+AHU+VAV, 보일러+FCU |

실무에서는 **혼합**이 보통입니다 — 예: 외기는 DOAS(Air Loop), 실내 부하는 VRF(Zone Equipment).
EnergyPlus는 이 혼합을 `ZoneHVAC:EquipmentList` 의 **우선순위**로 처리합니다.

## 4-2. 존 ↔ 설비 접점 — `ZoneHVAC:EquipmentConnections`

모든 액티브 요소는 이 객체를 거칩니다.

```idf
ZoneHVAC:EquipmentConnections,
  <존 이름>,
  <ZoneHVAC:EquipmentList 이름>,   !- 이 존에 붙은 기기 목록
  <급기 노드(목록)>,                !- 존으로 들어오는 공기
  <배기 노드>,                      !- 존에서 나가는 공기
  <존 공기 노드>,                   !- 존 공기 상태를 대표하는 노드
  <환기 노드>;                      !- 리턴
```

```idf
ZoneHVAC:EquipmentList,
  <이름>,
  SequentialLoad,            !- 부하 분배 방식
  <기기1 종류>, <기기1 이름>, 1, 1,    !- 냉방·난방 우선순위 1
  <기기2 종류>, <기기2 이름>, 2, 2;    !- 우선순위 2
```

> **우선순위가 에너지 결과를 바꿉니다.** 예를 들어 복사난방을 1순위, 공조기를
> 2순위로 두면 복사난방이 먼저 부하를 처리하고 남은 것만 공조기가 담당합니다.
> 순서를 바꾸면 같은 기기 구성으로도 에너지 소요량이 달라집니다.
> **VE 검토에서 이 설정을 고정하지 않으면 대안 비교가 무의미해집니다.**

## 4-3. 공조계통(Air Loop) 구성

```
AirLoopHVAC
  ├─ Supply Side (공급측)
  │    Branch: OA System → 냉각코일 → 가열코일 → 팬
  │    AirLoopHVAC:OutdoorAirSystem
  │        OutdoorAir:Mixer  (외기 + 환기 혼합)
  │        Controller:OutdoorAir  (외기량 제어, 이코노마이저)
  │        HeatExchanger:AirToAir:SensibleAndLatent  (전열교환)
  │
  └─ Demand Side (수요측)
       AirLoopHVAC:SupplyPath → ZoneSplitter → AirTerminal:* → 각 존
       각 존 → ZoneMixer → AirLoopHVAC:ReturnPath
```

말단기기 18종 중 주요한 것:

| 말단 | 용도 |
|---|---|
| `AirTerminal:SingleDuct:VAV:Reheat` | **가장 범용적인 VAV** |
| `:VAV:NoReheat` | 재열 없는 VAV |
| `:VAV:Reheat:VariableSpeedFan` | 팬 포함 VAV |
| `:ConstantVolume:Reheat` / `:NoReheat` | CAV |
| `:SeriesPIU:Reheat` / `:ParallelPIU:Reheat` | 팬 파워드 유닛 |
| `:ConstantVolume:FourPipeBeam` | **액티브 빔** |
| `:ConstantVolume:CooledBeam` | 칠드빔 |
| `:ConstantVolume:FourPipeInduction` | 유인 유닛 |
| `:Mixer` | **DOAS + 존 기기 혼합** ← 국내 VRF+외기 구성에 필수 |
| `AirTerminal:DualDuct:*` | 이중덕트 |

> `AirTerminal:SingleDuct:Mixer` 가 중요합니다. **DOAS로 외기만 공급하고 실내
> 부하는 VRF/FCU가 담당하는 국내 흔한 구성**을 표현하는 객체입니다.
> `AirLoopHVAC:DedicatedOutdoorAirSystem` 과 함께 씁니다.

## 4-4. 열원(Plant Loop) 구성

```
PlantLoop
  ├─ Supply Side (열원측)
  │    Branch: 펌프 → 열원기기(병렬 가능) → 바이패스
  │    Splitter / Mixer 로 병렬 구성
  │    PlantEquipmentOperationSchemes  ← 운전 순서·부하 분배
  │
  └─ Demand Side (부하측)
       Branch: 코일·FCU·복사패널 (병렬)

CondenserLoop   (수냉식일 때)
  ├─ Supply: 냉각탑 또는 GroundHeatExchanger
  └─ Demand: 냉동기 응축기측
```

**운전 제어(`Plant-Condenser Control` 17종)가 에너지 결과를 크게 좌우합니다.**

| 객체 | 역할 |
|---|---|
| `PlantEquipmentOperationSchemes` | 열원 가동 순서 총괄 |
| `PlantEquipmentOperation:CoolingLoad` / `:HeatingLoad` | **부하 구간별 가동 기기 지정** |
| `PlantEquipmentOperation:OutdoorDryBulb` 등 | 외기 조건별 전환 |
| `PlantEquipmentOperation:ComponentSetpoint` | 기기별 설정값 운전 |
| `SetpointManager:*` (29종) | 송수온도 리셋 등 |

> **냉동기 2대를 병렬로 넣기만 하면 안 됩니다.** `PlantEquipmentOperation:CoolingLoad`
> 로 "부하 0~50%는 1대, 50~100%는 2대" 같은 가동 전략을 지정해야 부분부하 효율이
> 제대로 반영됩니다. 이 설정을 빼면 실제보다 효율이 나쁘게 나옵니다.

## 4-5. 적용 순서 권고

```
1단계  IdealLoadsAirSystem 으로 순수 부하 확인
       → 패시브 요소 VE 검토는 여기서 끝낼 수 있음
2단계  존 기기만 배치 (FCU/VRF/복사) — Air Loop 없이
       → 존 단위 설비 대안 비교
3단계  Air Loop 추가 (외기·전열교환·이코노마이저)
       → 환기 전략 검토
4단계  Plant Loop 추가 (열원·축열·지열)
       → 열원 대안 비교
5단계  Electric Load Center 추가 (신재생)
       → ZEB 자립률 검토
```

**단계마다 결과를 저장해 두십시오.** 뒤 단계에서 이상한 값이 나왔을 때
어느 단계에서 틀어졌는지 역추적할 수 있습니다.

# 5. 신재생에너지 시스템 구성 및 적용 방법

## 5-1. ★ 두 개의 접속점 — 전기계와 열계

신재생 시스템은 **연결되는 계층이 다릅니다.** 이것을 먼저 구분해야 합니다.

```
          ┌──────────────── 전기계 ────────────────┐
PV / 풍력 / 연료전지 / 마이크로CHP
          ↓
   ElectricLoadCenter:Generators      발전기 목록 + 가동 순서
          ↓
   ElectricLoadCenter:Inverter:*      DC → AC
          ↓
   ElectricLoadCenter:Storage:*       축전지 (선택)
          ↓
   ElectricLoadCenter:Distribution    ★ 운전 전략 + 계통 연계
          ↓
   건물 전력 수요와 합산 → 순수입/순수출 전력 산출
          → 'Electric Loads Satisfied' 표 → ZEB 자립률


          ┌──────────────── 열계 ─────────────────┐
태양열 집열기 / 지중열교환기 / 수열원 히트펌프
          ↓
   PlantLoop 의 Supply Side 에 기기로 배치
          ↓
   급탕 탱크 또는 냉온수 루프로 열 공급
          ↓
   보조 열원 사용량 감소로 에너지 절감이 나타남
```

> **중요**: 태양열은 전기계에 넣을 수 없고, PV는 열계에 넣을 수 없습니다.
> **PVT(태양광열 복합)는 양쪽에 동시에 들어갑니다** — 5-4절 참조.

## 5-2. 전기계 — 구성 방법

### 발전기 선택 (`Electric Load Center-Generator Specifications` 32종)

| 종류 | 객체 | 성능 입력 방식 |
|---|---|---|
| **태양광 (간이)** | `Generator:PVWatts` + `ElectricLoadCenter:Inverter:PVWatts` | **용량·설치형태만** — NREL PVWatts 모델 |
| 태양광 (간이2) | `Generator:Photovoltaic` + `PhotovoltaicPerformance:Simple` | 효율 고정값 |
| 태양광 (등가 1-다이오드) | `+ PhotovoltaicPerformance:EquivalentOne-Diode` | 모듈 전기 파라미터 |
| **태양광 (Sandia)** | `+ PhotovoltaicPerformance:Sandia` | **제품별 실측 계수** (`datasets/SandiaPVdata.idf`) |
| **풍력** | `Generator:WindTurbine` | 회전자 직경·정격풍속·파워곡선 |
| **연료전지** | `Generator:FuelCell` + 7개 부속 객체 | 상세 (전기+열 동시) |
| **마이크로 CHP** | `Generator:MicroCHP` + `:NonNormalizedParameters` | 열병합 |
| 내연기관 발전 | `Generator:InternalCombustionEngine` | |
| 가스터빈 | `Generator:CombustionTurbine` | |
| 마이크로터빈 | `Generator:MicroTurbine` | |

### 인버터·축전지·변압기

| 객체 | 용도 |
|---|---|
| `ElectricLoadCenter:Inverter:Simple` | 효율 상수 |
| `:Inverter:FunctionOfPower` | 부하율별 효율 곡선 |
| `:Inverter:LookUpTable` | 표 입력 |
| `:Inverter:PVWatts` | PVWatts 전용 |
| `:Storage:Simple` | **간이 축전지** (효율·용량만) |
| `:Storage:Battery` | 상세 (Kinetic Battery Model) |
| **`:Storage:LiIonNMCBattery`** | **리튬이온 NMC 상세 모델** |
| `:Storage:Converter` | AC↔DC 변환기 |
| `:Transformer` | 변압기 손실 |

### 운전 전략 — `ElectricLoadCenter:Distribution`

이 객체가 **ZEB 자립률 결과를 결정합니다.** 발전 전력을 어떻게 쓸지 정합니다.

| 전략 유형 | 의미 |
|---|---|
| Baseload | 정격 출력 고정 운전 |
| DemandLimit | 계통 수입을 목표치 이하로 유지 |
| TrackElectrical | 건물 전력 수요를 추종 |
| TrackSchedule / TrackMeter | 스케줄·계량기 추종 |
| FollowThermal / FollowThermalLimitElectrical | **열 수요 추종** (CHP용) |

축전지 충방전 제어도 여기서 지정합니다
(예: `FacilityDemandLeveling`, `TrackFacilityElectricDemandStoreExcessOnSite`).

> **PV 단독 ZEB 검토라면** `Generator:PVWatts` + `Inverter:PVWatts` +
> `Distribution`(TrackElectrical) 3개 객체로 끝납니다. 가장 빠른 경로입니다.
> 제품 선정 단계에서 `PhotovoltaicPerformance:Sandia` 로 정밀화하십시오.

## 5-4. ★ PVT — 전기계와 열계 동시 연결

ZEB 검토에서 가치가 큰 조합입니다.

| 객체 | 설명 |
|---|---|
| `SolarCollector:FlatPlate:PhotovoltaicThermal` | PVT 집열기 본체 |
| `SolarCollectorPerformance:PhotovoltaicThermal:Simple` | 간이 성능 |
| **`SolarCollectorPerformance:PhotovoltaicThermal:BIPVT`** | **건물일체형 PVT (BIPVT)** |

PVT는 하나의 기기가 **전기와 열을 동시에** 생산하므로,
`Generator:Photovoltaic`(전기계)과 `PlantLoop`(열계)에 **양쪽으로 연결**합니다.

> **BIPVT가 ZEB 설계에 유용합니다.** 외피 일체형이므로 설치 면적 제약이 큰
> 국내 도심 건물에서 자립률을 올리는 수단이 됩니다. 다만 외피 열적 거동과
> 발전이 상호작용하므로 입력 난이도가 높습니다.

## 6-1. 열원 (28종)

# 7. 종합 — 에너지 분석 로직의 특징과 한계

## 7-1. 강점

| 항목 | 내용 |
|---|---|
| **설비-건물 연동** | 설비 성능이 실내온도에 되먹임. 용량 부족·부분부하 효율이 결과에 반영 |
| **동적 축열** | CTF/유한차분으로 구조체 축열을 시간 단위로 계산 |
| **시스템 표현력** | 877개 객체. 상용 설비의 대부분을 표현 가능 |
| **신재생 통합** | 발전·저장·계통 연계를 건물 부하와 한 모델에서 합산 → ZEB 자립률 직접 산출 |
| **경제성 내장** | 요금체계·LCC·공사비를 같은 모델에서 계산 ([`09`](09-심화-요금체계와VE경제성.md)) |

## 7-2. 한계 — 검토 시 반드시 인식할 것

| 한계 | 내용 | 대응 |
|---|---|---|
| **존 완전혼합 가정** | 기본적으로 존 공기를 1점으로 봄 | `Room Air Models` 17종 또는 CFD 별도 |
| **1차원 열전달** | 벽체는 1D. 3차원 열교 직접 계산 불가 | `Foundation:Kiva`(2D/3D 기초), 외부 열교 해석 후 선형열관류율 반영 |
| **AirflowNetwork 제약** | `AirLoopHVAC` 1개만, 덕트 열용량 무시 | 계통 다수면 침기만 사용 ([`08`](08-심화-기밀성능과결로.md)) |
| **고온지열 미구현** | `High Temperature Geothermal*` | 해당 없음 |
| **성능곡선 의존** | 기기 성능은 곡선·표로 외부 입력 | 제조사 데이터 또는 `datasets/PerfCurves.idf`, Curve Fit Tool |
| **단일 코어 순차 계산** | 1회 해석은 병렬화 불가 | 케이스 단위 병렬 ([`04`](04-자동화.md)) |

## 7-3. 국내 적용 시 교체·보완이 필요한 것

| 항목 | 내장 데이터 | 국내 적용 |
|---|---|---|
| **기상데이터** | 미국 TMY3 등 37개 | 기상청 데이터 변환 필요. **직달/확산 분리가 선행 과제** |
| **에너지 단가** | 미국 요금제 예제 | `UtilityCost:*` 로 한전 요금제 직접 구성 |
