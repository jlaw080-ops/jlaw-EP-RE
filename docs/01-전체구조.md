# 01. 전체 구조 — 설치 폴더와 원본 소스의 대응

## 1-1. 설치 폴더 ↔ 소스 저장소 대응표

`C:\EnergyPlusV26-2-0` 안의 각 항목이 원본 소스의 어디서 왔는지 정리했습니다.
(근거: 소스의 `cmake/Install.cmake` — 설치 패키지를 만드는 규칙 파일)

| 설치 폴더 안의 항목 | 정체 | 원본 소스 위치 |
|---|---|---|
| `energyplus.exe` | 계산 엔진 본체 | `src/EnergyPlus/` 243개 `.cc` 컴파일 결과 |
| `Energy+.idd` | **입력 규칙서(스키마)** — 가장 중요 | `idd/Energy+.idd.in` |
| `Energy+.schema.epJSON` | 위 IDD를 JSON Schema로 변환한 것 | `idd/schema/generate_epJSON_schema.py` 로 생성 |
| `ExampleFiles\` | 예제 입력파일 819개 | `testfiles/` |
| `WeatherData\` | 샘플 기상데이터 (미국 5개 도시) | `weather/` |
| `DataSets\` | 재료·기기 성능 라이브러리 | `datasets/` |
| `MacroDataSets\` | 매크로용 데이터셋 | `datasets/Macro/` |
| `Documentation\` | 공식 PDF 문서 | `doc/` (LaTeX/Markdown 원본) |
| `PreProcess\` | 전처리 도구 (IDF Editor, ExpandObjects 등) | `src/IDF_Editor/`, `src/ExpandObjects/` 등 |
| `PostProcess\` | 후처리 도구 (ReadVarsESO 등) | `src/ReadVars/`, `src/ConvertESOMTR/` 등 |
| `LICENSE.txt` | 라이선스 | `LICENSE.txt` |
| `Bugreprt.txt` | 버그 신고 안내 | `release/Bugreprt.txt` |

**핵심**: 설치 폴더에서 분석 가치가 가장 높은 단 하나의 파일은 `Energy+.idd` 입니다.
이것은 바이너리가 아닌 **사람이 읽을 수 있는 텍스트**이고,
"EnergyPlus가 받아들이는 모든 입력의 전체 목록과 규칙"이 들어 있습니다.
사용자님 PC에서 메모장으로 바로 열어볼 수 있습니다. (4.6MB라 느릴 수 있음 → VS Code 권장)

## 1-2. 소스 저장소 디렉터리 지도

```
energyplus-src/
├── src/
│   ├── EnergyPlus/          ★ 계산 엔진 본체 (243 .cc / 75.9만 줄)
│   │   └── api/             ★ 외부 프로그램 연동용 API (Python/C)
│   ├── Transition/            버전 간 입력파일 자동 변환기
│   ├── ExpandObjects/         HVACTemplate 축약입력 → 정식입력 확장
│   ├── IDF_Editor/            입력파일 GUI 편집기
│   ├── ReadVars/              .eso 바이너리성 출력 → CSV 변환
│   ├── Basement/, Slab/       지중 열전달 전처리 (Fortran)
│   └── EP-Launch/             실행 런처
├── idd/
│   ├── Energy+.idd.in      ★ 입력 스키마 원본 (877개 객체 / 11.1만 줄)
│   └── schema/             ★ IDD → epJSON 스키마 변환 파이썬 코드
├── doc/
│   └── engineering-reference/ ★ 계산식 공식 문서 (592개 파일)
├── testfiles/                 예제 입력파일 819개
├── datasets/                  재료·기기 라이브러리 56개
├── weather/                   샘플 기상데이터 37개
├── third_party/               외부 라이브러리 25개
└── cmake/Version.cmake        버전 정의 (26.2.0)
```

## 1-3. 내장 외부 라이브러리 — "엔진 속의 엔진"

EnergyPlus가 직접 계산하지 않고 외부 라이브러리에 맡기는 부분이 있습니다.
이 목록은 **어떤 계산이 EnergyPlus 자체 알고리즘이 아닌지**를 알려주므로
알고리즘 검증 시 중요합니다.

| 라이브러리 | 담당 계산 | 도메인 관련성 |
|---|---|---|
| `Windows-CalcEngine` | 창호 광학·열 성능 (LBNL WINDOW 엔진) | ★ 패시브하우스 창호 검토 |
| `kiva` | 지반 접지 2D/3D 열전달 | ★ 바닥 열교·지중 손실 |
| `penumbra` | GPU 기반 그림자 계산 | 외부 차양 검토 |
| `ssc` | NREL SAM 계산 모듈 (PVWatts 등) | ★ 태양광 발전량 |
| `DElight` | 주광 조도 계산 | 자연채광 검토 |
| `btwxt` | 다차원 성능곡선 보간 | 기기 부분부하 성능 |
| `libtk205` | ASHRAE 205 기기 성능 데이터 표준 | 기기 성능 입력 |
| `SQLite` | 결과 DB 출력 | ★ 결과 자동 추출의 핵심 |
| `nlohmann` (JSON) | epJSON 입출력 파싱 | ★ 입력 자동 생성 |
| `ObjexxFCL` | Fortran 호환 배열 라이브러리 | (레거시 흔적) |
| `FMI`/`FMUParser`/`BCVTB` | 외부 시뮬레이터 공동연동 | 고급 연동 |
| `eigen`, `re2`, `fast_float`, `zlib`, `milo`, `Expat`, `valijson`, `CLI`, `gtest` | 범용 유틸리티 | - |

> `ObjexxFCL`의 존재는 EnergyPlus의 역사를 말해줍니다.
> 원래 Fortran으로 작성된 프로그램(1996년, IBLAST/BLAST 계보)을
> C++로 기계 번역하면서 Fortran 배열 문법을 흉내내는 라이브러리를 끼워넣은 것입니다.
> 그래서 소스 곳곳에 1-based 배열 같은 Fortran식 코드가 남아 있습니다.
> **소스를 읽을 때 "왜 이렇게 이상하게 짰지?" 싶은 부분은 대부분 Fortran 레거시입니다.**
