# EnergyPlus 26.2.0 해부 프로젝트 (jlaw-EP-RE)

건축설비·신재생에너지 VE / ZEB / 패시브하우스 검토 업무를 자동화하기 위해
EnergyPlus 26.2.0의 내부 구조를 분석한 기록입니다.

---

## 0. 가장 먼저 알아야 할 결론 3가지

### (1) EnergyPlus는 리버스엔지니어링이 필요 없습니다 — 오픈소스입니다

`C:\EnergyPlusV26-2-0` 안의 `energyplus.exe`를 역분석하는 것은
**불필요하게 어려운 길**입니다. EnergyPlus는 미국 에너지부(DOE)가 자금을 대고
LBNL·일리노이대·ORNL 등이 개발한 **완전 공개 소스** 프로그램입니다.

- 원본 저장소: https://github.com/NREL/EnergyPlus
- 본 분석 기준: **태그 `v26.2.0`** (설치본과 동일 버전)
- C++ 소스 전체, 입력 스키마, 공식 계산식 문서(Engineering Reference)가 모두 공개

즉 "역분석"이 아니라 **"원본 읽기"** 로 같은 목적을 달성할 수 있습니다.

### (2) 라이선스는 자유롭지만, "이름"에 함정이 있습니다 — 웹서비스 계획에 직결

라이선스는 BSD 3-Clause 계열이라 **상업적 이용·수정·재배포가 모두 허용**됩니다.
단 원문 `LICENSE.txt`에 일반 BSD에는 없는 **제4항**이 추가되어 있습니다.

> 회사명·제품명·광고·홍보 활동에 `EnergyPlus`, `E+`, `e+` 또는
> 혼동을 줄 수 있는 유사 명칭을 **DOE의 사전 서면 동의 없이 사용할 수 없다.**
> 또한 소프트웨어를 수정 없이 단독 배포하거나 제품의 소프트웨어 부분만을
> 지칭할 때는 반드시 `"EnergyPlus version X" software` 로 표기해야 한다.

**실무적 의미**: 나중에 웹서비스를 만들 때 서비스명을
`EnergyPlus 자동검토`, `E+ Cloud` 같은 식으로 지을 수 없습니다.
서비스명은 독자적으로 짓고, 내부적으로
"본 서비스는 EnergyPlus version 26.2.0 software를 사용합니다"
와 같이 **기능 설명 문구로만** 언급하는 방식이 안전합니다.
(법적 판단은 아니며, 상용화 단계에서는 별도 검토 권장)

### (3) 규모를 알고 접근해야 합니다 — 전체를 읽는 것은 불가능합니다

| 항목 | 실측값 (v26.2.0) |
|---|---|
| C++ 소스 파일 | 243개 `.cc` + 290개 `.hh` |
| 총 코드 줄 수 (`src/EnergyPlus`) | 약 **75.9만 줄** |
| 입력 객체(IDD 클래스) 종류 | **877개** |
| 입력 스키마 파일 크기 | `Energy+.idd` 약 4.6MB / 11.1만 줄 |
| 공식 예제 입력파일 | 819개 (`testfiles/`) |
| 공식 문서 소스 | 592개 파일 (`doc/engineering-reference`) |
| 내장 외부 라이브러리 | 25개 (`third_party/`) |

75만 줄을 통독하는 것은 의미가 없습니다.
**목적별로 진입점(entry point)을 잡아 그 경로만 따라가는 것**이 유일한 방법이며,
이 프로젝트 문서는 그 진입점 지도입니다.

## 2. 기상데이터

한국 기준기상연도(TRY) **22개 지점**이 `weather/` 에 고정 보관되어 있습니다.
기상청 실측(2005~2014)을 ISO 15927-4 로 가공한 데이터입니다.

```bash
python3 scripts/weather/fetch.py
```

`weather/epw/` 에 `.epw`·`.ddy`·`.stat` 가 풀립니다. 네트워크가 필요 없습니다.
상세는 [`docs/11-기상데이터관리.md`](docs/11-기상데이터관리.md).

> **자동 업데이트하지 않습니다.** 기준년은 재현성이 목적이므로 버전을 고정하고,
> 상위 배포본 변경만 월 1회 자동 감시해 Issue 로 알립니다.

## 3. 분석 환경 재현 방법

```bash
GIT_LFS_SKIP_SMUDGE=1 git clone --depth 1 https://github.com/NREL/energyplus ./energyplus-src
```

```bash
cd ./energyplus-src && git fetch --depth 1 origin tag v26.2.0 && git checkout v26.2.0
```

> 버전을 반드시 맞추십시오. `develop` 브랜치 최신은 이미 **27.1.0**(차기 버전 개발 중)이며,
> 26.2.0과 모듈 구성·입력 객체가 다릅니다. 버전이 어긋나면 분석 결과가 설치본과 맞지 않습니다.
